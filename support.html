Deployment Support

Last updated: June 20, 2026

This page provides deployment guidance for submitting the GYMatch mobile app to the Google Play Store and Apple App Store. It includes required store assets, build checklist items, review preparation, and common troubleshooting steps.

Use this page as a reference while preparing release builds, app store metadata, and privacy compliance materials.

Release Readiness Checklist

  • Confirm app version numbers are updated for release: versionCode / buildNumber.
  • Verify the app bundle/package identifier is correct for each platform.
  • Test the production build on real devices and emulators.
  • Confirm privacy policy, support email, and terms are available and accurate.
  • Ensure third-party sign-in and location permissions work in production mode.
  • Confirm app store screenshots, icons, and description match the published experience.

Required App Metadata

Prepare the following data before submitting to either store:

  • App name and subtitle/title.
  • Short description and full description.
  • App category and target audience.
  • Privacy policy URL (for example, https://gymatch.com/privacy-policy).
  • Support contact email (for example, support@gymatch.com).
  • App screenshots for required device types.
  • App icon and feature graphic / promotional images.

Google Play Store

Key steps

  • Use Android App Bundle (.aab) for the Play Store if possible.
  • Enable Google Play App Signing and upload the correct signing key.
  • Confirm the package name matches the app's package settings.
  • Upload the correct privacy policy URL and contact information in the Play Console.
  • Complete the Data Safety form and declare all required permissions.
  • Set the content rating and target audience accurately.
  • Review the Play Store policy checklist for restricted content, location usage, and user data handling.

Build & signing

  • Run a release build on Android: flutter build appbundle --release or relevant Gradle command.
  • Use the production signing key and keep the upload key secure.
  • Increment versionCode for every new release.
  • Test the signed release APK/AAB on a physical device before upload.

Apple App Store

Key steps

  • Use App Store Connect to create a new app record and attach the correct bundle ID.
  • Use TestFlight for beta testing and App Store review prep.
  • Provide a valid support email and marketing URL if available.
  • Complete App Privacy details and any required questionnaire about data collection.
  • Include a privacy policy URL and clearly describe how location, sign-in, and messaging features are used.
  • Upload required screenshots for all supported device families.
  • Ensure the app uses permission descriptions in Info.plist for location and camera/microphone access if needed.

Build & signing

  • Use the correct distribution certificate and provisioning profile.
  • Set the build number for every App Store submission.
  • Use flutter build ios --release or Xcode archive with the app set to release configuration.
  • Verify the app runs in a signed, production configuration before upload.
  • Confirm the bundle ID and App Store Connect record are aligned.

Testing and Review

  • Validate app behavior for login, onboarding, location access, and chat features.
  • Use internal test tracks on Google Play and TestFlight on Apple for reviewer testing.
  • Verify the app does not crash on supported devices and handles permission denial gracefully.
  • Ensure push notifications and backend connectivity work after signing in release mode.
  • Keep release notes clear and mention any known limitations or new functionality.

Common Deployment Issues

  • Missing or invalid privacy policy URL in the store listing.
  • Incorrect package name or bundle ID between app configuration and store settings.
  • Unsubmitted Data Safety form on Google Play.
  • Bad permissions descriptions or missing Info.plist keys for iOS.
  • Release build crashes due to debug-only code, API keys, or environment configuration.
  • Expired certificates or provisioning profiles for Apple builds.
  • App metadata that does not match the actual app experience.
